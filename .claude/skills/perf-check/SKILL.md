# 성능 측정

**측정 없이 "빨라졌다"고 말하지 않는다.** 이 게임의 성능 예산은 권고가 아니라 제약이다.

## 예산

| 시나리오 | 기준 |
| --- | --- |
| 적 300체 + 투사체 200개 | 프레임 **16.6ms 이내** (60FPS) |
| 최악 프레임 (p99) | 33ms 이내 (한 번씩 끊겨도 30FPS는 유지) |
| GC 일시정지 | 프레임당 0회가 목표 |

## 측정 절차

### 1. 스트레스 모드 실행

```powershell
npm run dev
```

브라우저에서 `?stress=1`을 붙여 접속한다. 스트레스 모드는 적 300체·투사체 200개를 즉시 스폰하고 HUD에 프레임 타이머를 띄운다.

> 스트레스 모드가 아직 없으면 먼저 만든다. `src/engine/stress.ts`에 스폰 루틴을 두고 쿼리 파라미터로 켠다.

### 2. 프레임 타이밍 확인

내장 계측이 표시하는 값:

```
frame  12.4ms   sim 4.1  collide 5.2  render 3.1   entities 487  pool 0 alloc
```

`pool N alloc`이 **0이 아니면 루프 안에서 할당이 일어나고 있다.** 즉시 원인을 찾는다.

### 3. 브라우저 프로파일러

Chrome DevTools → Performance → 10초 녹화.

| 볼 것 | 정상 |
| --- | --- |
| Scripting | 프레임당 10ms 이하 |
| GC (노란 톱니) | 거의 없음 |
| Rendering + Painting | 프레임당 4ms 이하 |
| Long Task | 없음 |

## 위반 시 점검 순서

프레임이 예산을 넘으면 **아래 순서대로** 의심한다. 대개 1~3에서 잡힌다.

1. **루프 안 할당** — `new`, 객체 리터럴, `map`/`filter`/스프레드. 벡터 결과 객체를 재사용하는가?
2. **오브젝트 풀 미사용** — 적·투사체·데미지 텍스트가 매 프레임 생성/폐기되는가?
3. **O(n²) 충돌** — 공간 해시를 거치지 않고 전수 비교하는가? 셀 크기가 적 반지름 대비 적절한가?
4. **컬링 누락** — 화면 밖 오브젝트를 그리고 있는가?
5. **배치 미적용** — 같은 스프라이트를 모아 그리지 않고 매번 상태를 바꾸는가?
6. **캔버스 상태 변경 과다** — `save`/`restore`, `fillStyle` 변경 횟수.
