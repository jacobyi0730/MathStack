# 태스크 완료 처리

**"다 됐다"고 말하기 전에 이 절차를 거친다.** 완료 조건을 통과하지 못한 태스크는 완료가 아니다.

## 1단계 — DoD 검증

태스크 파일의 `## 완료 조건 (DoD)` 항목을 **하나씩 실제로 확인한다.** 체크박스를 눈으로 보고 넘기지 않는다.

공통 게이트 — 해당하는 것만:

```powershell
npm run typecheck
npm run lint
npm run test
npm run build:bank ; if ($?) { npm run validate:bank }
npm run build
```

| 건드린 것 | 추가 게이트 |
| --- | --- |
| 게임 루프·충돌·렌더 | `perf-check` 스킬 |
| 문항·템플릿 | `build-bank` 스킬 |
| 적·무기 | 문서·데이터·코드 3곳 일치 확인 |
| 문서 | `new-doc` 스킬의 인덱스 등록 |
| 빌드·배포 설정 | Netlify 순서 전체 재현 |

**하나라도 실패하면 완료가 아니다.** 실패를 보고하고 멈춘다.

## 2단계 — 태스크 파일 갱신

프런트매터의 `status`를 바꾼다.

```yaml
status: done        # todo | doing | blocked | done
```

본문 맨 아래에 **결과 메모**를 남긴다. 다음 사람이 읽을 것이다.

```markdown
## 결과

- 구현: `src/systems/spawn.ts`, `src/data/waves.ts`
- 측정: 적 300체 14.2ms (2026-08-20, Chrome 141, 1920×1080)
- 남은 것: 이리듐 유성 드롭 확률은 T-014에서 조정 예정
```

**설계와 다르게 구현한 부분이 있으면 반드시 적는다.** 왜 달라졌는지까지.

## 3단계 — TodoList 갱신 ★

**[TodoList.md](../../../TodoList.md) 가 완료 상태의 유일한 정본이다.** 해당 줄을 `[~]` 에서 `[x]` 로 바꾸고 완료일과 실행자를 적는다.

```markdown
- [x] **T-005** 오브젝트 풀 & 공간 해시 — `game-engine-dev` ✅ 2026-08-20
```

**함께 할 것**

| 갱신 | 내용 |
| --- | --- |
| 후속 태스크 | 선행이 전부 `[x]` 가 된 줄을 `[-]` → `[ ]` 로 푼다 |
| 현황 줄 | `N / 28 완료 · 진행 중 M · 착수 가능 K` |
| 배정 이력 표 | 실행자(Claude 에이전트 / codex)와 결과를 기록 |
| 알려진 결함 | 남은 문제가 있으면 줄 끝에 `⚠` 로 짧게 남긴다. 다음 착수자가 본다 |

`Tasks/README.md` 는 **구조만** 담는다(선행·담당·스킬). **상태 컬럼이 없으므로 건드리지 않는다.**

태스크 파일 프런트매터의 `status` 는 TodoList 의 **거울**이다. 둘이 어긋나면 **TodoList 가 이긴다.**

> **작업 에이전트는 TodoList 를 수정하지 않는다.** 상태 갱신은 오케스트레이터 전담이다 — 여러 실행자가 같은 줄을 고치면 그 자체가 충돌이다. 위임받아 일한 경우라면 이 단계는 보고만 하고 넘긴다.

## 4단계 — 후속 태스크 해제

이 태스크를 선행으로 걸고 있던 것을 찾는다.

```powershell
Select-String -Path "TodoList.md","Tasks/*.md" -Pattern "T-007"
```

TodoList 에서 선행이 모두 `[x]` 가 된 줄을 **`[-]` → `[ ]`** 로 바꾼다. 이게 다음 라운드에 **병렬로 돌릴 수 있는 후보**가 된다.

## 5단계 — 문서 반영

구현 중에 **기획서의 수치나 설계가 실제와 달라졌다면** 문서를 고친다. 코드가 정본이 되는 것을 허용하지 않는다.

- 밸런스 수치가 바뀌었다 → `balance-tuner`
- 기획서 자체를 바꿔야 한다 → `doc-keeper`에게 맡기고, 설계 결정을 뒤집는 변경이면 사용자에게 먼저 알린다

## 완료 조건

- [ ] DoD 전 항목을 실제로 확인했다
- [ ] 해당하는 게이트 명령이 전부 통과했다
- [ ] **위임해서 받은 결과라면 게이트를 오케스트레이터가 직접 다시 돌렸다** — 실행자의 "완료했다"를 그대로 믿지 않는다
- [ ] 태스크 파일 `status: done`, 결과 메모 작성
- [ ] **`TodoList.md` 를 `[x]` 로 갱신**하고 현황·배정 이력을 맞췄다
- [ ] 후속 태스크의 `[-]` 를 `[ ]` 로 풀었다
- [ ] 남은 결함이 있으면 TodoList 줄에 `⚠` 로 남겼다
- [ ] 설계와 달라진 부분을 문서에 반영했다
