# 새 문서 만들기

**표에 없는 문서는 없는 문서다.** 파일 생성과 인덱스 등록은 한 세트다.

## 1단계 — 위치와 번호 정하기

| 번호대 | 폴더 | 다루는 것 |
| --- | --- | --- |
| 00 | `docs/` | 기획서 (정본) |
| 10 | `docs/10-게임디자인/` | 코어루프, 적, 무기, 아트, 성장곡선 |
| 20 | `docs/20-수학커리큘럼/` | 성취기준, 문제유형, 출제규칙 |
| 30 | `docs/30-기술/` | 아키텍처, 파이프라인, 스키마, 성능, 배포 |
| 40 | `docs/40-운영/` | 셋업, 테스트전략 |

파일명은 **`NN-한글이름.md`**. 공백 대신 하이픈을 쓴다. 번호는 해당 폴더에서 다음 빈 번호.

## 2단계 — 파일 생성

프런트매터는 필수다.

```markdown
---
title: 콘텐츠 파이프라인
status: draft        # draft | review | stable
owner: 기술          # 기획 | 기술 | 수학
updated: 2026-08-20  # 오늘 날짜
related: [31-아키텍처, 33-데이터스키마]
---

# 32. 콘텐츠 파이프라인

> 한 줄 요약 — 이 문서가 무엇을 정하는가.

## 1. ...
```

## 3단계 — 본문 규칙

- **수치는 표로.** 산문에 묻어두면 코드로 옮길 수 없다.
- **결정에는 근거를 한 줄.** "쿨타임 3초" 뒤에 왜 3초인지.
- **미결정은 `TBD:`로 표기.** 방치하지 않는다.
- **기획서와 충돌하지 않는다.** 기획서가 상위 정본이다. 바꿔야 한다면 기획서를 먼저 고친다.

## 4단계 — 인덱스 등록 ★

`AGENTS.md` §4의 해당 표에 한 줄 추가한다. **이 단계를 빼먹으면 작업 미완료다.**

```markdown
| 32 | [32-콘텐츠파이프라인.md](docs/30-기술/32-콘텐츠파이프라인.md) | 템플릿 DSL, 전개·검증 규칙, 산출물 계약 | 🚧 |
```

상태 표시: ✅ 작성 완료 · 🚧 작성 중 · 📝 예정

**내용이 비어 있으면 ✅를 붙이지 않는다.** 껍데기 문서를 완료로 표시하는 것이 인덱스를 못 믿게 만드는 가장 빠른 길이다.

## 5단계 — 링크 확인

새 문서가 참조하는 상대 경로가 실제 파일을 가리키는지 확인한다. `docs/30-기술/`에서 기획서를 가리키면 `../MathStack기획서.md`다.
