# 성취기준 검증

문항의 `standard` 코드가 틀리면 **이 게임의 존재 이유가 사라진다.** 의심되면 반드시 확인한다.

## 코드 체계 (2022 개정 교육과정)

```
4수01-16
│ │ │  └─ 성취기준 일련번호
│ │ └──── 영역 (01~04)
│ └────── 교과 (수학)
└──────── 학년군 (4 = 3~4학년군, 6 = 5~6학년군)
```

| 영역 코드 | 영역명 |
| --- | --- |
| `01` | 수와 연산 |
| `02` | 변화와 관계 |
| `03` | 도형과 측정 |
| `04` | 자료와 가능성 |

**학년군 코드는 학년이 아니다.** `4수`는 3학년과 4학년 둘 다에 쓰인다. 실제 학년 배정은 기획서 §13의 매핑표가 정한다.

## 검증 절차

### 1. 코드 실재 확인

```powershell
# 기획서 매핑표에 있는지
Select-String -Path "docs/MathStack기획서.md" -Pattern "4수01-16"
```

없으면 **그 코드는 이 프로젝트에서 쓰지 않는 코드다.** 매핑표에 추가해야 할 정당한 이유가 있는지 먼저 판단한다.

### 2. 학년군 정합성

| `grade` | 허용 접두 |
| --- | --- |
| 3, 4 | `4수` |
| 5, 6 | `6수` |

### 3. 학년·학기 배정

기획서 §13의 해당 학년 표에서 그 코드가 어느 학기에 배정됐는지 확인한다. **아직 안 배운 내용을 내면 안 된다** — 3학년 1학기 학생에게 2학기 분수 문항은 금지다.

### 4. 출제 적합도

매핑표의 적합도 칸을 본다.

| 표시 | 처리 |
| --- | --- |
| ◎ | 그대로 출제 |
| ○ | 도형·그래프 이미지(인라인 SVG) 필요 |
| △ | 제한적. 형태를 바꿔야 출제 가능 |
| ✕ | **출제 금지.** §13.5 제외 목록 |

### 5. 개념 선행 검사

문항 본문에 **상위 학년 개념이 섞였는지** 확인한다. 흔한 사고:

| 학년 | 섞이면 안 되는 것 |
| --- | --- |
| 3 | 분수의 곱셈/나눗셈, 소수 둘째 자리 이상, 약분 |
| 4 | 최대공약수·최소공배수, 분모가 다른 분수 계산 |
| 5 | 비와 비율, 원주율, 비례식 |
| 6 | 문자와 식, 음수 |

## 매핑표에 없는 코드가 필요할 때

1. 실재하는 성취기준인지 웹에서 확인한다 (교육부 고시, 시도교육청 성취수준 자료).
2. §13.5 제외 사유에 해당하지 않는지 본다.
3. 기획서 §13의 해당 학년 표에 행을 추가한다 — **doc-keeper 에이전트에게 맡긴다.** 기획서는 상위 정본이므로 임의 수정하지 않는다.

## 완료 조건

- [ ] 코드가 기획서 §13 매핑표에 실재한다
- [ ] `grade`와 학년군 접두가 맞다
- [ ] 학기 배정이 맞다
- [ ] 적합도가 ✕가 아니다
- [ ] 문항 본문에 상위 학년 개념이 없다
