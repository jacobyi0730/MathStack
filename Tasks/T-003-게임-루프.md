# T-003 · 게임 루프 & 고정 타임스텝

## 목표

시뮬레이션과 렌더를 분리한 고정 타임스텝 루프를 만든다. **이후 모든 시스템이 이 루프의 계약 위에서 돈다.**

## 범위

- [ ] `src/engine/loop.ts` — `requestAnimationFrame` 기반, 누산기(accumulator) 방식
- [ ] 시뮬레이션 **1/60초 고정**, 렌더는 매 프레임
- [ ] `dt` 상한 **0.25초** — 탭 복귀 시 시뮬레이션 폭주 방지
- [ ] `src/engine/state.ts` — `createGameState()` 단일 상태 객체
- [ ] `src/engine/timing.ts` — 프레임 계측 (sim/collide/render 구간별 ms, 엔티티 수, 풀 할당 수)
- [ ] 일시정지 API — 퀴즈 모달이 쓸 `pause()` / `resume()`

## 계약

```ts
// 시스템은 전부 이 형태의 순수 함수다
export function update(state, dt) {}   // dt는 항상 초 단위, 고정 1/60
```

- **전역 상태 금지.** `createGameState()`가 만든 객체를 명시적으로 전달한다.
- **`document` 참조 금지.** DOM은 `src/ui/`의 일이다.
- **`await`·`fetch` 금지.** 런타임 서버가 없다.

## 산출물

| 경로 | 내용 |
| --- | --- |
| `src/engine/loop.ts` | 고정 타임스텝 루프 |
| `src/engine/state.ts` | 게임 상태 팩토리 |
| `src/engine/timing.ts` | 프레임 계측 |

## 완료 조건 (DoD)

- [ ] 60FPS·144Hz 모니터 양쪽에서 **시뮬레이션 속도가 동일**하다
- [ ] 탭을 30초 백그라운드로 두었다 돌아와도 폭주하지 않는다
- [ ] `pause()` 중 시뮬레이션이 진행되지 않는다
- [ ] 계측 오버레이가 프레임 ms를 표시한다
- [ ] `npm run lint` · `npm run test` 통과

## 주의

가변 타임스텝으로 시작하고 나중에 고치겠다는 유혹을 받아들이지 않는다. 충돌·물리가 전부 `dt`에 물려 있어서, 나중에 바꾸면 밸런스 수치를 전부 다시 잡아야 한다.

### DoD 검증

| 항목 | 결과 |
| --- | --- |
| 60Hz·144Hz·30Hz 시뮬레이션 속도 동일 | 1초에 59~60스텝, **주사율 간 차 ≤ 1스텝** |
| 누적 드리프트 없음 | **10분(36,000프레임) 후 게임 시간 오차 ≤ 1스텝** |
| `dt` 는 항상 `FIXED_DT` | 불규칙 프레임(7·33·16·120ms)에도 단일값 확인 |
| 탭 30초 백그라운드 후 폭주 없음 | 한 프레임 최대 `MAX_STEPS_PER_FRAME`(5) |
| 스파이크 후 backlog 토해내기 없음 | 이후 10프레임에서 추가 스텝 ≤ 10 |
| `pause()` 중 시뮬레이션 정지 | 60프레임 진행해도 `updates`·`elapsedSec` 불변 |
| `pause()` 중 렌더는 계속 | 퀴즈 모달 뒤 화면 유지 (기획서 §14.3) |
| 계측 오버레이 | `frame/sim/collide/render/steps/entities/pool` 표시 |

### 설계 판단

1. **주사율 간 1스텝 차는 버그가 아니다.** 프레임 간격(`1000/60`)이 이진 부동소수점으로 딱 떨어지지 않아 1초 경계의 마지막 스텝이 다음 프레임으로 밀린다. 누산기가 나머지를 이월하므로 **누적되지 않으며**, 10분 테스트가 그것을 증명한다. 처음엔 `toBe(60)`으로 썼다가 사실에 맞게 고쳤다.

2. **`MAX_STEPS_PER_FRAME` 도달 시 누산기를 0으로 버린다.** 안 버리면 다음 프레임이 더 밀려 죽음의 나선이 된다. 시간을 잃되 멈추지는 않는 쪽을 택했다.

3. **`LoopClock` 을 주입 가능하게 만들었다.** `requestAnimationFrame` 에 묶여 있으면 노드 환경에서 테스트가 불가능하다. 이 결정 덕분에 DoD 전부를 단위 테스트로 옮길 수 있었다.

4. **`resync()` 를 노출했다.** 델타 상한만으로도 폭주는 막히지만, `visibilitychange` 에서 그 프레임을 아예 버리는 편이 정확하다. `main.ts` 에서 연결했다.

5. **`alpha`(보간 계수)를 `render` 에 넘긴다.** T-004 렌더러가 이걸 써야 144Hz 에서 부드럽게 보인다. 지금은 회전 지표가 미리 쓰고 있다.

### 경계를 넘은 것

`src/ui/debug-overlay.ts` 는 **ui-builder 담당 영역**이다. 하지만 "계측 오버레이가 프레임 ms 를 표시한다"가 T-003 의 DoD 이고, `engine/` 은 `document` 를 만질 수 없다(36-코딩컨벤션 §4). 계측값 생산(`engine/timing.ts`)과 표시(`ui/debug-overlay.ts`)를 나눠 경계를 지켰다. T-023 HUD 작업 시 ui-builder 가 이 파일의 스타일을 함께 볼 것.
