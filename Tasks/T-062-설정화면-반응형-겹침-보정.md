# T-062 · 설정 화면 반응형 겹침 보정

## 요청

시작 화면의 설정 UI 가 PC 와 모바일에서 적절히 표시되는지 확인한다. PC 에서 버튼이 겹친다.

## 무엇이 잘못돼 있었나

헤드리스 Chrome 으로 네 해상도(1920×1080 · 1366×768 · 390×844 · 360×640)를 실측했다. **네 곳 모두에서 「돌아가기」가 화면 밖에 있었다.**

| 해상도 | 「돌아가기」 위치 | 뷰포트 |
| --- | --- | --- |
| 1920×1080 | top 1038 ~ bottom 1094 | 1080 |
| 1366×768 | 791 ~ 847 | 768 |
| 390×844 | 867 ~ 923 | 844 |
| 360×640 | 663 ~ 719 | 640 |

원인은 **스크롤 컨테이너가 두 겹**이었다는 것이다. 타이틀 흐름의 `section` 과 그 안의 설정 화면이 **둘 다** `max-height: calc(100dvh - 24px)` 를 갖는다. 안쪽이 바깥쪽의 `padding: 20px` 와 버튼 자리를 모르는 채 뷰포트 높이를 통째로 차지해, 바깥에 있던 버튼이 아래로 밀렸다.

## 완료 조건 (DoD)

- [x] PC(1920·1366)와 모바일(390·844, 360×640)에서 「돌아가기」가 항상 보인다.
- [x] 항목끼리 겹치지 않는다.
- [x] 가로 스크롤바가 생기지 않는다.
- [x] 일시정지 메뉴도 같은 해상도에서 확인한다.
- [x] `npm run typecheck`, `npm run lint`, `npm run test`, `npm run build` 가 통과한다.

## 결과

- 구현

  - `src/ui/title.ts` — 설정 화면을 `minmax(0,1fr) auto` 두 줄로 만들어 **목록만 흐르고 「돌아가기」는 바닥에 고정**. 설정 화면만 `min(960px,100%)` 로 넓게

- 문서: `docs/05-세션-운영.md` §14.3.2

| --- | --- | --- | --- | --- |

일시정지 메뉴는 같은 해상도에서 겹침 0 · 가로 넘침 0 · 「그만하기」 보임으로 이상 없었다.

## 파고들어 알아낸 것 — 겹침의 진짜 원인

「돌아가기」를 바닥에 고정하자 이번에는 **카드끼리 겹쳤다.** 처음엔 `align-content: start` 로 고칠 문제라고 봤는데, 지정해도 그대로였다. 실측해 보니 여섯 개 행이 전부 **93.83px** 로 눌려 있었다 — `(708 − 제목 37 − 상태 24 − 간격 84) ÷ 6` 과 정확히 일치한다.

> 높이가 확정된 그리드에서 암시적 `auto` 행은 남은 공간을 **균등 분배**받는다. 내용이 넘치면 분배량이 음수가 되어 행이 내용보다 짧아지고, 카드 글자가 다음 카드에 덮인다.

`grid-auto-rows: max-content` 를 주자 행이 131/234/158/138/138/131 로 돌아오고 `scrollHeight` 가 1075 로 잡히며 정상 스크롤됐다. **`align-content` 로는 못 막는다** — 이건 정렬이 아니라 트랙 크기 문제다.

두 번째로, `minmax(300px, 1fr)` 은 컨테이너가 300px 보다 좁은 360px 폰에서 칸이 컨테이너를 넘어 **가로 스크롤바**를 만들었다. `minmax(min(100%, 300px), 1fr)` 로 바꿔 막았다.

둘 다 회귀 테스트로 고정했다.

## 설계 결정

- **PC 에서는 두 열로 흘린다.** 가로는 남아도는데 세로가 모자라는 상황이었다. 남는 쪽을 쓰면 1080p 에서 스크롤이 아예 사라진다.
- **스티키 버튼 대신 고정 푸터를 썼다.** 처음엔 `position: sticky` 로 붙였는데, 모바일에서 버튼이 목록 **위에 떠서** 뒤의 항목을 가렸다. 스크롤 영역과 푸터를 그리드 두 줄로 나누면 겹칠 수가 없다.
- **`embedded` 를 옵션으로 뒀다.** 설정 화면을 단독으로 띄울 여지를 남기되, 타이틀 안에 들어갈 때는 카드와 스크롤을 바깥에 양보한다.
