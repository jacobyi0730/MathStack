# T-018 · 뱅크 검증기 `validate:bank`

## 목표

**빌드를 곧 검증으로 만든다.** 성취기준이 틀린 문항 하나로 배포가 실패하는 것이 의도된 동작이다.

## 검사 항목

Zod 스키마(T-016)가 형식을 잡고, 이 도구가 **도메인 규칙**을 잡는다.

| 검사 | 실패 조건 |
| --- | --- |
| 성취기준 실재 | `standard`가 `shared/curriculum.ts`에 없음 |
| 학년 정합성 | `grade`와 코드 학년군 불일치 (3·4↔`4수`, 5·6↔`6수`) |
| 학기 정합성 | `semester`가 매핑표와 다름 |
| 오개념 태그 | `misconceptionTag`가 빔 |
| 오답 근거 | `distractorReason.length !== choices.length` |
| 근거 내용 | 근거가 빈 문자열이거나 `"정답"`만 반복 |
| **정답 유일성** | `answer`가 `choices`에 없거나 2회 이상 |
| 선택지 중복 | `choices`에 같은 값 2개 이상 |
| 출제 제외 | 적합도 `✕` 코드 사용 (§13.5) |
| **영역 비중** | 학년별 뱅크가 §12.5 목표 비중(45/30/15/10%)을 채울 수 없음 |
| 난이도 분포 | 난이도 1~5 각 구간에 최소 문항 수 미달 |
| 응답 시간 | `timeLimitSec`이 10~20 범위 밖 |

## 범위

- [ ] `tools/validate-bank.ts` — 위 검사 전부
- [ ] **실패 시 `process.exit(1)`.** 경고 출력 후 계속 진행하지 않는다
- [ ] 리포트 출력 — 학년별 문항 수, 영역 분포, 난이도 분포, 실패 목록
- [ ] `tests/tools/validate.test.ts` — 각 검사가 실제로 잡는지 확인 (일부러 깨진 문항 투입)

## 주의

**검증을 느슨하게 만들려는 압력이 반드시 온다.** 문항 저작 중 실패가 잦으면 검사를 끄고 싶어진다. 그때가 이 검증기가 일하고 있다는 증거다. 기준을 낮추지 말고 문항을 고친다.
