# T-005 · 오브젝트 풀 & 공간 해시

## 목표

적 300체 + 투사체 200개를 **할당 없이** 다루기 위한 두 자료구조를 만든다. 이걸 나중에 붙이면 전부 다시 짜야 한다.

## 범위

### 오브젝트 풀 (`src/engine/pool.ts`)

- [ ] `createPool(factory, reset, capacity)` — 미리 할당, 런타임 확장 없음
- [ ] `acquire()` / `release(obj)` — 프리 리스트 방식
- [ ] 풀 고갈 시 정책: **가장 오래된 것 재활용** (예외 던지지 않음)
- [ ] 계측: 이번 프레임 신규 할당 수 (`pool alloc`, 목표 **0**)

풀 대상: 적, 투사체, 양성자 조각, 데미지 텍스트, 파티클.

### 공간 해시 (`src/engine/spatial-hash.ts`)

- [ ] `insert(entity)` / `clear()` / `queryNearby(x, y, radius, out)`
- [ ] 셀 크기는 **가장 흔한 적 반지름의 2배** 기준 (기본 64px)
- [ ] `queryNearby`는 **결과 배열을 인자로 받아 채운다** — 새 배열을 만들지 않는다
- [ ] 매 프레임 `clear()` 후 재삽입 (재구축이 증분 갱신보다 빠르고 단순하다)

## 계약

```ts
const out = [];                       // 루프 밖에서 한 번만 만든다
hash.queryNearby(x, y, r, out);       // out.length = 0 후 채움
for (let i = 0; i < out.length; i++) { ... }
```

## 완료 조건 (DoD)

- [ ] 적 300체 + 투사체 200개 시나리오에서 **`pool alloc` = 0**
- [ ] 충돌 후보 수가 전체 엔티티 수보다 한 자릿수 이상 작다
- [ ] `queryNearby`가 배열을 새로 만들지 않는다 (코드 확인)
- [ ] 풀 고갈 상황에서 크래시 없이 동작한다
- [ ] `perf-check` 스킬 통과 — 프레임 16.6ms 이내
- [ ] `npm run test` 통과 (풀 재사용·해시 질의 단위 테스트)

## 주의

셀 크기를 너무 작게 잡으면 셀 수가 폭증하고, 크게 잡으면 후보가 줄지 않는다. **실측으로 정한다** — 기본값 64px에서 시작해 `perf-check`로 조정한다.
