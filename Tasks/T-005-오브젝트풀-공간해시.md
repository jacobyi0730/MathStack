# T-005 · 오브젝트 풀 & 공간 해시

## 목표

적 300체 + 투사체 200개를 **할당 없이** 다루기 위한 두 자료구조를 만든다. 이걸 나중에 붙이면 전부 다시 짜야 한다.

## 범위

### 오브젝트 풀 (`src/engine/pool.ts`)

- [ ] `createPool(factory, reset, capacity)` — 미리 할당, 런타임 확장 없음
- [ ] `acquire()` / `release(obj)` — 프리 리스트 방식
- [ ] 풀 고갈 시 정책: **가장 오래된 것 재활용** (예외 던지지 않음)
- [ ] 계측: 이번 프레임 신규 할당 수 (`pool alloc`, 목표 **0**)

풀 대상: 적, 투사체, 양성자 조각, 데미지 텍스트, 파티클.

### 공간 해시 (`src/engine/spatial-hash.ts`)

- [ ] `insert(entity)` / `clear()` / `queryNearby(x, y, radius, out)`
- [ ] 셀 크기는 **가장 흔한 적 반지름의 2배** 기준 (기본 64px)
- [ ] `queryNearby`는 **결과 배열을 인자로 받아 채운다** — 새 배열을 만들지 않는다
- [ ] 매 프레임 `clear()` 후 재삽입 (재구축이 증분 갱신보다 빠르고 단순하다)

## 계약

```ts
const out: Enemy[] = [];                    // 루프 밖에서 한 번만 만든다
const n = hash.queryNearby(x, y, r, out);   // 개수를 반환하고 out 을 채운다
for (let i = 0; i < n; i++) { ... }         // out.length 가 아니라 n 까지만 읽는다
```

> **구현 시 `out.length = 0` 방식에서 바꿨다.** 길이를 0으로 줄이면 백킹 스토어가 축소돼 다음 프레임에 다시 늘어난다 — 매 프레임 재할당이 생긴다. 길이를 건드리지 않고 **반환값까지만 읽는 계약**이 진짜로 할당 없는 유일한 방법이다.

## 완료 조건 (DoD)

- [ ] 적 300체 + 투사체 200개 시나리오에서 **`pool alloc` = 0**
- [ ] 충돌 후보 수가 전체 엔티티 수보다 한 자릿수 이상 작다
- [ ] `queryNearby`가 배열을 새로 만들지 않는다 (코드 확인)
- [ ] 풀 고갈 상황에서 크래시 없이 동작한다
- [ ] `perf-check` 스킬 통과 — 프레임 16.6ms 이내
- [ ] `npm run test` 통과 (풀 재사용·해시 질의 단위 테스트)

## 주의

셀 크기를 너무 작게 잡으면 셀 수가 폭증하고, 크게 잡으면 후보가 줄지 않는다. **실측으로 정한다** — 기본값 64px에서 시작해 `perf-check`로 조정한다.

### 설계 판단

1. **풀은 스왑 파티션 구조를 썼다.** 배열 하나를 활성/비활성으로 나누고 경계만 움직인다. 프리 리스트가 따로 없어 획득·반납이 O(1) 이고, **활성 구간이 항상 조밀해 매 프레임 순회가 빠르다.** 시스템이 `items[0..activeCount)` 를 그냥 훑으면 된다.

2. **고갈 시 예외를 던지지 않는다.** 가장 오래된(`poolSeq` 최소) 항목을 회수해 재사용한다. 게임이 멈추느니 오래된 적 하나가 사라지는 편이 낫다. 스폰 상한(T-007)이 제대로 동작하면 이 경로는 타지 않으며, `recycles > 0` 이 **풀이 작다는 신호**로 남는다.

3. **이중 반납·타 풀 객체 반납을 조용히 무시한다.** 소유권 검사(`items[index] !== item`)로 걸러낸다. 게임 루프에서 예외가 터지는 것이 최악이다.

4. **공간 해시는 Map 이 아니라 고정 격자다.** 월드가 무한해서 Map 을 쓰면 플레이어가 움직일 때마다 새 셀 키가 생겨 무한히 자란다. 대신 **플레이어 중심으로 매 프레임 다시 놓는 64×64 격자**(4,096×4,096px 커버)를 쓴다. `clear()` 는 `Int32Array.fill(0)` 한 번이다.

5. **항목은 중심 셀에만 넣고 질의 반경을 넓힌다.** AABB 가 걸치는 모든 셀에 중복 삽입하는 것보다 싸고, 이번 프레임 최대 반지름만큼 넓히면 놓치는 것이 없다. **전수 비교와 결과가 같음을 테스트로 확인**했다.

6. **`queryNearby` 는 개수를 반환하고 `out` 을 채운다.** `out.length` 를 줄이면 백킹 스토어가 축소돼 다음 프레임에 다시 늘어난다. 길이를 건드리지 않고 반환값까지만 읽는 계약으로 두었다 — 이 계약을 테스트로 못 박았다.

### 열화 지점을 숨기지 않았다

격자 밖(`outsideCount`)·셀 상한 초과(`overflowCount`)를 세어 노출한다. 조용히 버리면 "가끔 안 맞는 총알"로 나타나 원인을 찾기 어렵다. 값이 0이 아니면 격자를 넓히거나 `maxPerCell` 을 올리라는 신호다.

### 남은 것

- 아직 `main.ts` 에 연결하지 않았다. 실제 사용은 T-007(적 스폰)·T-008(충돌)
