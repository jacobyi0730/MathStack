# T-036. 퀴즈 보기 가독성

## 배경

4지선다 보기 버튼이 번호를 `1. ` 형태로 **답 바로 앞에 이어 붙여** 렌더하고 있었다. 답이 정수일 때는 문제가 없지만 소수가 나오면 `2. 2.5` 가 되어 어디까지가 번호이고 어디부터가 답인지 읽히지 않는다. 소수 단원은 4~6학년 전 학년에 걸쳐 나오므로 특정 문항의 문제가 아니라 구조의 문제다.

번호를 그냥 지우는 선택지도 있었지만 그러면 **숫자 키 1~4 로 보기를 고르는 키보드 조작(T-027 접근성)이 가리킬 대상을 잃는다.** 번호는 남기되 답과 시각적으로 분리하는 쪽을 택했다.

## 범위

- 보기 번호를 답과 같은 줄의 글자가 아니라 **원형 배지**로 분리 (34px 원, 남색 배경, 흰 글자)
- 배지의 마침표 제거 (`1. ` → `1`)
- 답 글자를 22px / 700 weight 로 키워 번호 배지(18px)보다 크게 배치 — 눈이 답에 먼저 닿게 한다
- 큰 글자 모드에서 보기(28px)와 숫자 입력칸(30px)도 함께 확대. 기존에는 문제 지문만 커졌다
- 배지는 `aria-hidden` 유지 — 스크린 리더는 답만 읽는다
- 퀴즈 모달 DOM 테스트를 저장소 관행(FakeDocument)으로 옮겨 **실제로 실행되게** 함

## 발견한 것

`vite.config.ts` 의 vitest 환경이 `node` 인데 `quiz-modal.test.ts` 만 `it.runIf(typeof document !== 'undefined')` 를 쓰고 있었다. 실제 `document` 가 없으므로 이 파일의 DOM 테스트 3개는 **한 번도 실행된 적이 없었다.** hud·result·skill-choice·settings 테스트가 쓰는 `FakeDocument` 관행으로 옮겨 8개 전부 실행되게 고쳤다.

- [x] 숫자 키 1~4 로 보기를 고르는 조작이 그대로 동작한다.
- [x] 스크린 리더가 번호 배지를 읽지 않는다.
