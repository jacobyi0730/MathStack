# T-019 · 학년별 문항 저작 (3~6)

## 목표

**이 게임의 존재 이유가 되는 태스크다.** 레퍼런스가 실패한 지점 — 학년별 문항의 단순함 — 을 여기서 해결한다.

## 규모 목표 (기획서 §12.9)

| 단계 | 학년당 고정 | 학년당 템플릿 | 학년당 유효 문항 |
| --- | --- | --- | --- |
| **MVP** | 40 | 10 | 약 640 |
| v1.0 | 100 | 30 | 약 1,900 |

**MVP를 먼저 완료하고 T-020으로 넘어간다.** 4개 학년 전부 v1.0을 채우려다 게임이 멈추면 안 된다.

## 영역 배분 (기획서 §12.5)

각 학년 뱅크가 이 비중을 **채울 수 있어야** 한다. 검증기가 확인한다.

| 영역 | 비중 |
| --- | --- |
| 수와 연산 | 45% |
| 도형과 측정 | 30% |
| 변화와 관계 | 15% |
| 자료와 가능성 | 10% |

**수와 연산만 채우고 끝내려는 유혹을 이긴다.** 그게 레퍼런스의 실패다.

## 난이도 배분

난이도 1~5가 각각 최소 15%씩 있어야 한다. 특히 **난이도 4(문장제)·5(역산·다단계)** 를 빠뜨리지 않는다. 초월 수련(T-025)이 난이도 4~5 고정이라 부족하면 구간이 성립하지 않는다.

## 작업 순서

학년별로 진행하되, **한 학년을 끝내고 다음으로 간다.** 4개 학년을 동시에 벌리면 품질이 흐트러진다.

1. 4학년 (스키마 검증용으로 가장 먼저)
2. 3학년
3. 5학년
4. 6학년

각 학년마다:
- [ ] 기획서 §13 해당 학년 매핑표에서 성취기준 목록 확보
- [ ] 적합도 `✕` 제외, `○`는 인라인 SVG 필요 여부 판단
- [ ] 영역별 목표 문항 수 산정
- [ ] `add-question-template` 스킬로 하나씩 작성
- [ ] `npm run build:bank && npm run validate:bank`

## 완료 조건 (DoD)

- [ ] 4개 학년 전부 MVP 규모(학년당 640문항) 달성
- [ ] `validate:bank` 리포트에서 4개 학년 모두 영역 비중 OK
- [ ] 난이도 1~5가 각 15% 이상
- [ ] 모든 문항에 `distractorReason`·`misconceptionTag`가 채워졌다
- [ ] 학년별 랜덤 20문항을 읽고 **학년 범위를 넘는 개념이 없음**을 확인했다
- [ ] gzip 크기가 학년당 150KB 이내

## 주의

**오답을 먼저 설계한다.** 정답부터 쓰고 오답을 나중에 채우면 반드시 무작위 숫자가 된다. "이 문항을 틀린 아이는 정확히 무엇을 모르는가"에 답할 수 없으면 그 문항은 버린다.

## 결과

- 검증: `validate:bank`에서 4개 학년 모두 영역 비중 OK, 난이도 1~5 OK
