# T-020 · 클라이언트 출제기

## 목표

레벨업 시 **어떤 문항을 낼지 결정하는 로직**을 브라우저에 구현한다. 서버가 없으므로 전부 클라이언트다.

## 범위

- [ ] `src/quiz/loader.ts` — 게임 시작 전 학년 뱅크 1개 로드 (`fetch`는 **여기서 딱 한 번**)
- [ ] `src/quiz/selector.ts` — 출제 알고리즘
- [ ] `src/quiz/grader.ts` — 채점, 3택/2택 보상 결정
- [ ] `src/quiz/session.ts` — 세션 상태(출제 이력, 영역 카운터, 오답 큐)

## 출제 알고리즘 (기획서 §12.6)

```
select(grade, semester, level, session):
  1. 재출제 큐가 비어있지 않고 level >= 10 → 큐에서 pop
  2. 아니면:
     a. 난이도 = 레벨↔난이도 분포에서 추첨
     b. 영역   = 가중 랜덤, 부족 영역이 있으면 강제
     c. 후보   = (학년, 학기≤현재, 영역, 난이도) 필터
     d. 이번 세션 출제분 제외 → 없으면 난이도 ±1 확장
  3. 선택지 셔플 후 반환
```

## 난이도 매핑 (기획서 §12.4)

| 레벨 | 분포 |
| --- | --- |
| 1~3 | 난이도 1 (100%) |
| 4~7 | 1(40%) / 2(60%) |
| 8~11 | 2(50%) / 3(50%) |
| 12~15 | 3(50%) / 4(50%) |
| 16~ | 4(60%) / 5(40%) |

**이 표를 코드에 하드코딩하지 않는다.** `src/data/quiz-rules.ts`로 뺀다.

## 영역 균형 (기획서 §12.5)

목표 비중 대비 **2문항 이상 뒤처진 영역이 있으면 강제 선택**한다. 이것이 레퍼런스와 갈라지는 지점이다.

## 채점 (기획서 §12.8)

| 결과 | 보상 |
| --- | --- |
| 1차 정답 | 스킬 **3택** |
| 오답 → 재도전 정답 | 스킬 **3택** (동일 보상) |
| 오답 → 재도전 오답 | 스킬 **2택** + 오개념 태그를 재출제 큐에 |
| 시간 초과 | 오답 처리, 단 재도전 기회는 소진되지 않음 |

**체력은 절대 깎지 않는다.**

## 완료 조건 (DoD)

- [ ] 게임 시작 시 자기 학년 뱅크만 로드한다
- [ ] **게임 루프 안에 `fetch`·`await`가 없다**
- [ ] 18문항 세션에서 영역 분포가 목표 대비 ±5%p 이내
- [ ] 레벨 구간별 난이도 분포가 표대로 나온다
- [ ] 한 세션에 같은 문항이 두 번 나오지 않는다
- [ ] 오답 시 체력이 줄지 않는다
- [ ] `npm run lint` · `npm run test` 통과 (출제 분포 통계 테스트 포함)

## 주의

출제 분포는 눈으로 확인이 안 된다. **1,000회 시뮬레이션 테스트**를 짜서 영역·난이도 분포가 목표에 수렴하는지 검증한다.
