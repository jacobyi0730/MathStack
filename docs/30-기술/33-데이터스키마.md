# 33. 데이터 스키마

> **정의는 `shared/schema.ts`의 Zod 스키마 하나뿐이다.** 이 문서는 그 스키마가 무엇을 뜻하는지 설명하고, 코드로 표현되지 않는 규칙을 정한다. 아래 JSON은 예시일 뿐 별도 정의가 아니다.

## 1. 문항 (`Question`)

```jsonc
{
  "id": "G4-N-015-03",           // <학년>-<영역>-<성취기준일련>-<변형>
  "grade": 4,                     // 3 | 4 | 5 | 6
  "semester": 2,                  // 1 | 2
  "domain": "수와 연산",          // 2022 개정 4개 영역 (§2)
  "unit": "분수의 덧셈과 뺄셈",
  "standard": "4수01-15",         // 2022 개정 성취기준 코드
  "difficulty": 2,                // 1(기초) ~ 5(심화)
  "format": "choice",             // choice | number_input
  "stem": "3/5 + 1/5 는 얼마인가요?",
  "choices": ["4/5", "4/10", "3/10", "2/5"],
  "answer": "4/5",
  "distractorReason": ["정답", "분모까지 더함", "분모끼리 더하고 분자는 뺌", "분자를 뺌"],
  "explanation": "분모가 같으면 분자끼리 더합니다.",
  "timeLimitSec": 15,
  "misconceptionTag": "fraction_denominator_add"
}
```

## 2. 영역 (`domain`) — 2022 개정 4개만

| 영역 | 코드 자리 | 예시 |
| --- | --- | --- |
| 수와 연산 | `01` | `4수01-15`, `6수01-08` |
| 변화와 관계 | `02` | `4수02-01`, `6수02-03` |
| 도형과 측정 | `03` | `4수03-24`, `6수03-16` |
| 자료와 가능성 | `04` | `4수04-02`, `6수04-01` |

**자유 문자열로 두지 않는다.** 2015 개정의 "규칙성" 같은 옛 영역명이 섞이면 영역 균형 출제가 조용히 깨진다. `shared/domain.ts`의 Enum으로 못 박아 컴파일 타임에 잡는다.

## 3. 규칙

- **오답은 실제 오개념에서 유도한다.** 무작위 숫자·정답±1 금지. `distractorReason`에 각 선택지의 근거를 남기고, 오답 3개는 **서로 다른 오개념**이어야 한다.
- **`misconceptionTag`를 비워두지 않는다.** 오답 복습 재출제의 키다.
- **`standard`는 실재해야 한다.** 학년군 코드(`4수`=3~4학년군, `6수`=5~6학년군)를 학년·학기로 분해한 매핑표는 [기획서 §13](../MathStack기획서.md#13-학년별-커리큘럼-매핑)에 있고, 코드로는 `shared/curriculum.ts`다.
- **`difficulty`와 게임 레벨의 매핑을 코드에 하드코딩하지 않는다.** [기획서 §12.4](../MathStack기획서.md#124-레벨--난이도-매핑)와 [23-출제-난이도규칙](../20-수학커리큘럼/23-출제-난이도규칙.md)에서만 정의한다.
- **영역 균형 출제**([기획서 §12.5](../MathStack기획서.md#125-영역-균형-출제-))를 지킨다. 수와 연산 편중은 이 프로젝트가 고치려는 바로 그 결함이다.
- 작도·자료 수집 등 실시간 퀴즈에 부적합한 성취기준은 출제하지 않는다 → [기획서 §13.5](../MathStack기획서.md#135-출제-제외-성취기준).
- 문항 추가·수정은 **`quiz-author` 에이전트**와 **`add-question-template` 스킬**을 거친다.

## 4. 검증 항목

`npm run validate:bank`이 잡는 것. 하나라도 걸리면 **빌드가 실패한다.**

| 검사 | 실패 조건 |
| --- | --- |
| 성취기준 실재 | `standard`가 `shared/curriculum.ts`에 없음 |
| 학년 정합성 | `grade`와 코드 학년군 불일치 |
| 학기 정합성 | `semester`가 매핑표와 다름 |
| 오개념 태그 | `misconceptionTag`가 빔 |
| 오답 근거 | `distractorReason.length !== choices.length` |
| 근거 내용 | 빈 문자열이거나 `"정답"`만 반복 |
| **정답 유일성** | `answer`가 `choices`에 없거나 2회 이상 |
| 선택지 중복 | `choices`에 같은 값 2개 이상 |
| 출제 제외 | 적합도 `✕` 코드 사용 |
| **영역 비중** | 학년별 뱅크가 목표 비중(45/30/15/10%)을 못 채움 |
| 난이도 분포 | 난이도 1~5 각 구간 최소 문항 수 미달 |
| 응답 시간 | `timeLimitSec`이 10~20 범위 밖 |

## 5. 밸런스 (`balance.json`)

`tools/build-balance.ts`가 문서의 수치를 모아 산출한다. 무기·보조·적·보스·성장곡선.

아이템·적 데이터에는 **`element`·`atomicNumber` 필드가 필수**다. 명명 체계([기획서 §6.1](../MathStack기획서.md#61-명명-규칙--원소--수학-))의 교육 가치를 도감·툴팁이 회수하는 통로다.

## 6. localStorage

```jsonc
{
  "version": 1,
  "best": { "survivalSec": 600, "kills": 512, "accuracy": 0.82 },
  "lastChoice": { "grade": 4, "semester": 2, "character": "hydrogen" },
  "misconceptions": { "decimal_alignment": { "wrong": 5, "converted": 3 } },
  "rankings": [{ "heroName": "원소 용사", "score": 1200, "survivalSec": 480, "kills": 50, "level": 8, "grade": 4 }],
  "settings": { "slowMode": false, "effectIntensity": 100, "largeText": false },
  "sessions": 12
}
```

**`version` 필드를 반드시 둔다.** 스키마가 바뀌었을 때 옛 데이터로 크래시나지 않게 마이그레이션 경로를 남긴다. 파싱 실패 시 초기화하고 진행한다 — 기록을 잃는 것이 게임이 안 켜지는 것보다 낫다.

**개인 식별 정보를 저장하지 않는다.** 용사 이름은 아이가 입력한 별명일 뿐이며, 실명 입력을 유도하지 않는다.
랭킹은 `heroName` 기준으로 묶어 같은 이름의 최고 점수 1개만 TOP 5 후보로 남긴다.
