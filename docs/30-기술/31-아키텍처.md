# 31. 아키텍처

> 이 저장소가 무엇으로 이루어져 있고, 어느 코드가 언제 도는지를 정한다.
> 전체 판단 근거는 [기획서 §15](../MathStack기획서.md#15-기술-구조-요약).

## 1. 두 개의 시간대

이 프로젝트의 코드는 **도는 시점**으로 나뉜다. 이것이 구조 전체를 결정한다.

| | 빌드 타임 | 런타임 |
| --- | --- | --- |
| 위치 | `tools/`, `content/` | `src/` |
| 언제 | 배포 전, 개발자 기계나 Netlify에서 1회 | 아이의 브라우저에서 매 프레임 |
| 하는 일 | 문항 저작·전개·검증, 밸런스 산출 | 게임 시뮬레이션, 출제, 채점, 렌더 |
| 산출 | `public/data/*.json` | 화면 |
| 배포 포함 | **아니오** | 예 (`dist/`) |

**서버는 없다.** Netlify 정적 호스팅이고, 서버리스 함수조차 쓰지 않는다. 게임 중 네트워크 왕복은 0회다.

## 2. 기술 스택

**언어는 TypeScript 하나다.** 두 시간대 모두.

| 레이어 | 선택 | 비고 |
| --- | --- | --- |
| 언어 | **TypeScript 5.x** (`strict: true`) | 빌드 타임·런타임 공통 |
| 런타임 | **Canvas 2D** | 게임 루프·렌더·입력·출제·채점 |
| 빌드 타임 | **tsx** 로 실행하는 `tools/*.ts` | |
| 스키마 | **Zod** | `shared/`에 한 번 정의 |
| 정확 연산 | **fraction.js · decimal.js** | 빌드 타임 전용 (`devDependencies`) |
| 번들러 | **Vite** | |
| 데이터 | 정적 JSON | 학년별 문항 뱅크, 밸런스 수치 |
| 기록 | `localStorage` | 개인 기록·오개념 이력 |
| 배포 | **Netlify** (정적) | publish `dist/` |
| 테스트 | **Vitest** | 양쪽 공통 |
| 포맷·린트 | Prettier + ESLint | |

## 3. `shared/` — 이 구조의 핵심

문항 스키마·영역 Enum·성취기준 매핑을 **Zod로 한 번 정의**하고, `tools/`(굽는 쪽)와 `src/`(읽는 쪽)가 같은 정의를 import 한다.

```
shared/schema.ts  ──┬──→  tools/build-bank.ts     (이 타입으로 굽는다)
                    ├──→  tools/validate-bank.ts  (이 타입으로 검증한다)
                    └──→  src/quiz/loader.ts      (이 타입으로 읽는다)
```

계약이 두 곳에 존재하지 않으므로 드리프트가 발생할 자리가 없다. **`tools/`나 `src/`에 같은 모양의 `interface`가 있다면 그건 버그다.**

이 프로젝트의 품질 서사는 통째로 "문항 뱅크가 정확해야 한다"이다. 그 계약에 이음매를 두지 않는 것이 언어를 TypeScript로 통일한 이유다.

## 5. 상태 소유권

| 상태 | 소유자 | 수명 |
| --- | --- | --- |
| 게임 시뮬레이션 (엔티티·좌표·HP) | `createGameState()` 단일 객체 | 세션 |
| 퀴즈 세션 (출제 이력·영역 카운터·오답 큐) | `src/quiz/session.ts` | 세션 |
| 문항 뱅크 | 게임 시작 시 1회 로드, 읽기 전용 | 세션 |
| 밸런스 수치 | `src/data/` + `public/data/balance.json` | 빌드 |
| 개인 기록·오개념 이력 | `localStorage` | 영구 |

**전역 상태를 만들지 않는다.** 게임 상태는 명시적으로 전달한다.

## 6. 데이터 흐름

```
[저작]   content/templates/*.ts + content/fixed/*.yaml
             │
[계약]   shared/schema.ts  ────────┐
             │ npm run build:bank  │
             ▼                     │
[검증]   npm run validate:bank  ← 실패 시 process.exit(1), 빌드 중단
             │                     │
             ▼                     │
[산출]   public/data/bank-g3…g6.json, balance.json
             │                     │
             │ vite build          │
             ▼                     ▼
[배포]   dist/ → Netlify      src/quiz/loader.ts 가 parse()
```

**빌드가 곧 검증이다.** 성취기준이 틀린 문항 하나로 배포가 실패하는 것이 의도된 동작이다.

## 7. 실행

```powershell
npm install

npm run build:bank        # 문항·템플릿을 고쳤을 때마다
npm run validate:bank     # 실패하면 배포도 실패한다

npm run dev               # http://localhost:5173
npm run typecheck         # tsc --noEmit
npm run lint
npm run test

# 프로덕션 확인 (Netlify와 동일한 순서)
npm ci && npm run build:bank && npm run validate:bank && npm run build && npm run preview
```

## 8. 하지 않는 것

| | 이유 |
| --- | --- |
| 서버·API 도입 | 정적 배포. 필요해지면 [기획서 §15.6](../MathStack기획서.md#156-학급-랭킹-v2-선택-기능)을 먼저 읽는다 |
| 게임 루프 안 `fetch`·`await` | 런타임 서버가 없다. 뱅크는 시작 전 1회 로드 |
| `public/data/`·`dist/` 편집·커밋 | 생성물이다 |
| `mds/` 수정 | 사용자 원본 요청 기록 |
| 빌드 타임 의존성을 `src/`에서 import | `fraction.js`·`decimal.js`가 번들에 새어 든다 |
