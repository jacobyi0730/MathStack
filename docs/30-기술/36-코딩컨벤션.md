# 36. 코딩 컨벤션

> 성능 규칙은 [34-성능예산](34-성능예산.md), 문항 계약은 [33-데이터스키마](33-데이터스키마.md)에 따로 있다.

## 1. 공통

- 들여쓰기 2칸. 최대 줄 길이 **100자**.
- 인코딩 UTF-8, 줄바꿈 LF (`.gitattributes`로 강제).
- **주석은 "왜"만 쓴다.** "무엇"은 이름으로 표현한다.
- 사용자에게 보이는 문자열은 한국어, **코드 식별자는 영어**. `적_체력` 같은 이름 금지.
- 매직 넘버 금지. 밸런스 수치는 `src/data/`, 문항 데이터는 `content/`로 뺀다.
- **수치의 정본은 문서다.** 문서와 `src/data/`가 다르면 문서를 고치고 데이터를 맞춘다.

## 2. TypeScript

- **`strict: true`.** `any` 금지 — 정말 필요하면 `unknown` 후 좁힌다.
- **Prettier** (single quote, semicolon, printWidth 100) + **ESLint flat config**.
- ES 모듈만. `require` 금지. 파일명은 `kebab-case.ts`.
- 네이밍: `camelCase` 함수·변수, `PascalCase` 타입·클래스, `SCREAMING_SNAKE` 모듈 상수.
- **타입은 `shared/`에서 온다.** `tools/`나 `src/`가 문항·밸런스 타입을 자체 정의하면 반려된다.
- 머지 조건: `npm run typecheck` 통과.

## 3. 빌드 타임 (`tools/`, `content/`)

`tools/`는 배포 산출물에 들어가지 않는다. 서버·API를 만들지 않는다.

- 각 도구는 **`npm run <script>`로 단독 실행**되고, 종료 코드로 성공/실패를 알린다. Netlify 빌드가 이 코드에 의존한다.
- 산출은 **`public/data/` 아래 JSON뿐.**
- 모든 문항은 **Zod `parse()`를 통과해야** 산출물에 들어간다. **검증 실패는 경고가 아니라 `process.exit(1)`**이다. 잘못된 문항이 배포되느니 배포가 실패하는 게 낫다.
- **전개는 결정적이어야 한다.** 시드 기반 PRNG를 인자로 넘긴다. **`Math.random()` 금지** — 전역 상태라 재현이 불가능하고 회귀 테스트가 성립하지 않는다.

### 3.1 부동소수점 금지 ★

**분수는 `fraction.js`, 소수는 `decimal.js`로 계산한다.**

```ts
3.42 + 1.8                       // 5.220000000000001  ← 이 값이 정답으로 구워진다
new Decimal(3.42).plus(1.8)      // 5.22               ← 이렇게 쓴다
```

float로 계산하면 오답이 오개념 때문이 아니라 **IEEE 754 때문에** 틀린 값이 되고, 오개념 기반 오답 설계([33-데이터스키마](33-데이터스키마.md))가 통째로 무너진다.

두 라이브러리는 `devDependencies`이며 **`src/`에서 import 하지 않는다.** 번들에 새어 들면 예산을 넘긴다.

```ts
// 좋음 — 순수 함수, 결정적, 정확 연산
export function expand(template: Template, count: number, seed: number): Question[] {
  const rng = makeRng(seed);
  ...
}
```

## 4. 런타임 (`src/`)

- **`class`는 엔티티에만** 쓰고, 시스템은 순수 함수로 작성한다 (`update(state, dt)`).
- 전역 상태 금지. 게임 상태는 `createGameState()`가 만든 단일 객체를 명시적으로 전달한다.
- DOM 조작은 `ui/`에서만. `engine/`·`systems/`는 `document`를 참조하지 않는다.
- 뱅크 JSON을 읽을 때 **Zod `parse()`를 한 번 태운다.** 굽는 쪽이 이미 검증했지만, 배포 사고나 캐시 꼬임을 여기서 잡는다.
- 게임 루프 규칙은 [34-성능예산](34-성능예산.md)에 있다. **협상 대상이 아니다.**

## 5. lint가 강제하는 규칙

[AGENTS.md §2 절대 규칙](../../AGENTS.md#2-절대-규칙) 중 기계로 잡을 수 있는 것은 `eslint.config.js`에 구현돼 있다. **규칙으로 막던 것을 도구로 막는 게 언제나 낫다.**

| 규칙 | ESLint | 적용 범위 |
| --- | --- | --- |
| `any` 금지 | `@typescript-eslint/no-explicit-any` | 전체 |
| 게임 루프 네트워크 금지 | `no-restricted-globals: fetch` | `src/engine`·`systems`·`entities` |
| 결정적 전개 (§3) | `no-restricted-properties: Math.random` | `tools/`·`content/` |
| 빌드 타임 의존성 격리 | `no-restricted-imports: fraction.js·decimal.js` | `src/` |

각 규칙의 `message`에 어긋난 스펙 번호가 들어 있다. 걸렸을 때 어디를 읽어야 하는지 바로 나온다.

**우회하지 않는다.** `eslint-disable`로 넘기고 싶어지면 그 순간이 설계를 다시 볼 때다.

## 6. TypeScript 6 주의

- **`baseUrl`은 폐기됐다** (TS5101). `paths`는 `tsconfig.json` 위치 기준 상대 경로(`./shared/*`)로 쓴다.
- `verbatimModuleSyntax`가 켜져 있으므로 타입만 가져올 때는 `import type`을 쓴다. `@typescript-eslint/consistent-type-imports`가 강제한다.

## 7. 테스트

- `tests/tools/` — 문항 뱅크 회귀. 템플릿 변경 시 정답이 바뀌지 않았는지.
- `tests/src/` — 런타임 단위 테스트.
- 파일명 `<대상>.test.ts`, 테스트명 `<대상>_<상황>_<기대결과>`.
- **출제 분포처럼 눈으로 확인 불가능한 것은 시뮬레이션 테스트로 검증한다.** 1,000회 돌려 영역·난이도 분포가 목표에 수렴하는지 본다.
